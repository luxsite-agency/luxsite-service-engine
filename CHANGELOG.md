# Зміни

Релізи — теги `vX.Y.Z` (нотатки GitHub генеруються з PR). Тут — зміни, які потребують дій від розгортань.

## Невипущене

- **Заявка: поле email і довільні поля форми.** `POST /lead` приймає `email` (необов'язкове; невалідна адреса — помилка
  форми без заявки) і ключі, які пак перелічив у `app.lead.extra_fields` (решта відкидається). Email — окрема колонка,
  лист-сповіщення (`Email:` і `Reply-To`), адмінка, контакт у Pipedrive/Bitrix24; довільні поля — JSON `service_lead.extra`,
  «Поля форми» в перегляді заявки, рядки в листі й CRM. Міграція `Version20261126110000`. Телефон обов'язковий, як був.
  Дія: пак, що дописував email чи адресу в `message` скриптом, переходить на окремі поля форми (`docs/site-pack.md`,
  «Форма заявки»). Bitrix24 із мапою `contact_fields: {EMAIL: email}` почне отримувати адресу — перевірити мапу.

- **Галочки «Не індексувати» для `/services/`, `/reviews/`, `/terms-of-service/` і `lastmod` у sitemap.xml.**
  Адмінка → «Налаштування сайту» → «Не індексувати»: сторінка отримує `noindex, follow` (meta й `X-Robots-Tag`) і
  зникає з карти. `lastmod` з дат БД тепер мають список послуг, категорії, райони, блог, «Про нас», FAQ, контакти,
  відгуки (якщо є) і юридичні сторінки; без нього лишається калькулятор. Без міграцій, типово галочки вимкнені.
  Дія: пак із власним `templates/services/sitemap.xml.twig`, копією старого шаблону (`e.uk`), видалити тим самим деплоєм
  (записи карти тепер `e['urls']`), увімкнути галочки й прибрати з шаблонів паку власний `noindex` цих сторінок.

- **HTML-поля адмінки — код як є, без Trix.** Описи послуг/категорій (і для міст), тексти міста й району, пости,
  сторінки, «Про нас» і юридичні тексти сайту — textarea з HTML моноширинним шрифтом замість візуального редактора
  TextEditorField. Trix переписував HTML усіх полів запису при збереженні, навіть нечіпаних (h2/h3, класи, table, ol →
  div, картинки → figure data-trix-attachment). Поле, значення якого не змінили (з точністю до переносів рядків і
  пробілів по краях), зберігається байт-у-байт. API `/api/admin/v1` без змін.
  Дія: записи, збережені через адмінку до викладки, могли вже втратити розмітку — перевірити тексти на `data-trix`
  і `<div>` замість заголовків (`SELECT … LIKE '%data-trix%'`) і відновити з бекапу/джерела.
- **Підтвердження Google Search Console через DNS TXT з адмінки бренду.** «Налаштування сайту» → SEO →
  «Google: підтвердження DNS (TXT)» (`seo.google_dns_verification`, до 5 значень; рядок `google-site-verification=…`
  зводиться до значення). При збереженні рушій ставить TXT на апекс бренду в Cloudflare і прибирає лише свої записи;
  стан по домену, «Стан у Cloudflare» і «Перевірити в DNS» — під списком налаштувань. Як підключити — `docs/site-ops.md`,
  «Підтвердження сайту в Google Search Console через DNS TXT».
  Дія: власник створює Cloudflare API token з правами лише **Zone:Read + DNS:Edit** і **лише на зони брендів цього
  розгортання** (окремий на розгортання) і кладе в `shared/.env.local` як `CLOUDFLARE_DNS_TOKEN=…` (600). Без токена все
  працює, TXT додається вручну за рядком з адмінки.
- **Файлів підтвердження на сайтах більше нема.** Прибрано `public/google3cc17ecbb1f93a59.html` (з v0.9.31 віддавався на
  всіх сайтах усіх розгортань, тобто одне ім'я файла на всі домени); `/google<hex>.html` і `/BingSiteAuth.xml` → 404.
  Міграція `Version20261120100000` видаляє рядки налаштувань файлового способу.
  Дія для сайту, підтвердженого цим файлом: **до викладки** додати в GSC тим самим акаунтом ресурс «Домен», поставити TXT
  вручну в DNS і підтвердити; після викладки вписати те саме значення в поле (дубля рушій не створить). Порядок —
  `docs/site-ops.md`, «Перехід сайту, підтвердженого файлом». Bing — імпортом з GSC.
