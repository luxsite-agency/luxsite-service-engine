# Як долучитися

Рушій розвиває LuxSite разом із запрошеними розробниками. Головна гілка `main` захищена: зміни потрапляють туди
лише через pull request, після зеленого CI і рев'ю мейнтейнера. Теги й релізи ставлять мейнтейнери.

## Порядок
1. Форк (або гілка в цьому репо для команди) від актуального `main`: `feat/…`, `fix/…`, `chore/…`.
2. Один PR — одна тема. Опис: навіщо, що змінено, як перевірено. Зміна поведінки сайту — з міграцією або параметром паку,
   типові сайти без заповнення мають виглядати як раніше.
3. CI має бути зеленим: `php -l`, `lint:twig`, `lint:yaml`, `lint:container`, схема сутностей проти ланцюга міграцій,
   `bash tests/site/run.sh` (shellcheck, валідатор реєстру й паків, сухі прогони `bin/site`).
4. Міграції лише адитивні; назви індексів — як генерує Doctrine.
5. Секрети, дампи, реальні домени й доступи клієнтів у репо не потрапляють (CI guard це перевіряє, але думайте й самі).

## Підпис внеску (DCO)
Кожен коміт підписуйте `git commit -s`: рядок `Signed-off-by: Ім'я <email>` означає, що ви маєте право передати цей код
під Apache License 2.0 ([Developer Certificate of Origin 1.1](https://developercertificate.org/)). PR без підпису не зливається.

## Стиль
PHP 8.4, `declare(strict_types=1)`, атрибути Doctrine, типізовані властивості. Коментарі пояснюють «навіщо», а не «що».
Параметри сайту — `app.*` у паку (`docs/site-pack.md`), не хардкод у рушії.
